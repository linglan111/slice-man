# Technical design

## Chapter ownership
Keep one main operation lease/AbortController across planning and dependent phases. Share admission/context/scheduling helpers and Zod-first contracts. For chapter-based operations, reuse current source-compatible Job.chapterPlan kind normal, including short clips. Recognition and person-name checking are exempt from chapter splitting; names retain the complete chronological timeline request. Retain existing single-owner chapter/cue assignment for chapter-based operations; label boundary evidence without duplicate mutations. Selection/range limits targets, not full chapter context.

Remove duration-based review bypass and intra-chapter subdivision. Admit complete serialized input and expected output before generation; reject oversized chapters with guidance to edit boundaries. Keep local evidence groups as validators while transporting full chapters. Update superseded whole-video one-shot tests/specs explicitly.

During repair, snapshot validated chapter boundaries and refresh membership after ASR; publish refreshed compatible plan metadata at validated commit. Do not replan each stage/loop. Later unrelated source edits retain normal invalidation; translation/style reuse plans.

## Concurrency and publication
Add defaulted API-profile text concurrency (existing effective default two), validate/persist/load legacy profiles. Move the visible setting from job settings to API service settings; retain legacy job field readability. Share a service limiter across operations/retries. Queue independent chapters promptly, release slots and settle workers on every terminal path.

Prepare immutable snapshots and merge report metadata against the latest validated base to prevent lost updates. Preserve existing guarantees: general translation can retain complete chapters; selected translation/name report/style publish complete validated operations; repair keeps a full round atomic across ASR/translation/adjudication. Verify revision, plan, mode, provider/key and abort immediately before publication.

## Names
Reproduce via isolated project/live configured service where accessible. Keep one complete chronological timeline name request, independent of normal/custom chapter plans. Do not call normalPlan, partition candidates by chapter, weaken the existing global two-cue recurrence rule or introduce cross-chapter proposal aggregation. Keep existing explicit capacity admission; no silent chunking or context truncation. Names may use the shared API-service limiter as one operation, without a chapter ID/prerequisite.

Keep exact literal/field-specific grounding authoritative, but correct its overly broad Unicode continuation boundary. Readonly original diagnostics show Latin edges touching Han/Hiragana wrongly rejected in ja -> zh-CN content. Use script-aware word boundaries that allow natural CJK adjacency/mixed Katakana-Latin aliases while preserving genuine word-fragment, digit/mark/underscore and UTF-16 boundary protection. Replay original diagnostics privately and add sanitized structural regressions. Prompt already distinguishes observed aliases from recommendations. Add one visible whole-request correction for actual JSON/shape/alias evidence failures, with trusted failure details and the same full-timeline context; none for auth/rate/network/truncation/cancel. Preserve global identity evidence, ambiguity safety, strict apply/undo and previous-report retention. Chapter-only edits must not change name prompts/results/applicability; source/translation/provider changes retain normal freshness checks.

## Repair
Fixed scope -> normal chapters -> batch missing checks -> qualifying target/old finding snapshot -> fresh ASR drafts -> chapter translation -> chapter old/new adjudication -> complete coverage/timing/text validation -> atomic round commit -> explicit target/dependency invalidation -> reassessment -> converge/cap.

Adjudication carries complete old chapter and relevant new chapter draft context, original-to-replacement mapping, suspicion opinions and old/new timing/source/translation. Require audited output for all targets with explicit split/merge/silence handling. Reject unknown/omitted targets, invalid times and unintended neighbor changes. All qualifying targets receive fresh ASR and enabled translation, replacing old category-only routing. ASR remains interval-based using existing complete-cue/recursive-overlap expansion, which stays visible.

Invalidate original target/replacement grades even if output is unchanged. Unknown/stale never means none. Preserve ignored intent only under existing compatibility rules. Reassess the final round at cap, then enter a separate final-consistency phase: re-read persisted assessments, collect all missing/recheck required cues (requested scope plus run-invalidated dependencies and expanded-ASR/new cues), and check them by canonical chapter with complete context, independent of threshold. This is assessment-only, does not consume/increase repair rounds and must not run repair invalidation afterward. Under the same operation lease, verify current complete grade coverage against the final persisted snapshot before publishing success/remaining counts. A successful stable check must drain the pending set; unchanged pending coverage or concurrent stale state is an actionable incomplete/error outcome, never an unbounded loop or a forced none grade. Failure/cancel retains committed content and pending states, with an explicit incomplete final-check status. Restart never resumes paid work. Failed/cancelled drafts never publish half a round or discard earlier committed rounds.

## Remaining text operations
Style uses chapter requests and deterministic aggregation under the existing single-global-style contract: earliest nonempty chapter by timeline supplies global visual settings under the same user request; merge validated emphasis from each owning chapter. No synthesis AI call. Chapter planning bootstraps from deterministic coverage without recursion; custom analysis batches normal chapters then validates aggregate output.

## Progress and compatibility
Use structured job/run/chapter/request progress: operation, phase, round/cap, completion/target counts, queue/active/terminal states and timestamps. Whole-timeline names show one analysis request and optional visible correction, without fictional chapter counts. Chapter help explicitly exempts recognition and names. Include a distinct final-consistency check phase with remaining pending cue/chapter counts, while retaining the last repair round/cap. Add run/chapter association to live snapshots as needed; never persist reasoning. Render every active request while keeping phase/round visible. Preserve accessible help, focus, scrolling and 1050x700 usability.

Default optional new fields safely, keep normal/custom enums/export compatibility. Actual client-service testing uses isolated copies, memory-only credentials and sanitized artifacts. No migration triggers network work. Roll back scoped child commits without reverting unrelated worktree edits.

## Coordination decisions after approval
- Profile textConcurrency defaults to 2 and accepts integer 1–16. The shared text transport limiter also covers the single global name request without chapter dependency.
- ProgressEvent.work carries run/operation/phase/round/counts plus queued/running/completed/failed/cancelled request entries. Live requests carry optional runId/chapterId. Renderer consumes this structured model rather than inferring workflow state from byte traffic.
- Remove the redundant heading stream button. Keep exactly one viewer action while processing; after completion a separate result row can retain that action for reopening. Never show both simultaneously.
- Core owns shared/backend chapter code; names edits only analyzeNames and name libraries/fixtures; progress owns renderer; later repair owns repair method/libraries and repair-loop E2E. Surgical shared-file edits must preserve teammates' changes. Main session does not implement product code.
- Final-consistency exit is conditional on its fresh scoped remaining count: new qualifying findings with budget left continue normal repair; only an actually exhausted cap produces max_rounds. This closes a final-check lifecycle edge without adding rounds to the check itself.
- Audits share cross-boundary fresh evidence, require per-target linkage, deduplicate only identical shared-ID results and reject new conflicting overlap while retaining inherited valid old/ASR overlap. Explicit target-level silence can coexist with neighbouring speech; empty source or stale/incomplete audited translation is invalid.
