# Design — AI chapters, recoverable operations and selected exports

## Architecture and ownership
1. `ai-streaming-diagnostics`: provider adapters/stream reader and request diagnostics files/SQLite schema+repository. Export a small typed observer/context API; no renderer secrets. Keep requestJson for audio/non-text transport rather than forcing SSE on ASR.
2. `chapter-translation-review`: shared chapter/run contracts, main chapter planner, Job metadata/freshness, default translation and incremental review orchestration. Depends on the first child's streaming/diagnostics contract. Own chapter planning IPC/preload; preserve existing service semantics.
3. `resumable-managed-tools`: shared artifact acquisition/cache helper, runtime and managed-tool installers/status. Independent of AI/chapters; retain atomic native activation.
4. `custom-chapter-export`: criteria persistence, selected range media/subtitle export and all integrated new chapter/criteria/export UI. Depends on chapter contracts/planner and streaming; no duplicate planner. Parent coordinates shared App/IPC/contract touch points and regression evidence.

Main code boundaries: `services/providers/lib/text-provider.ts`; new scoped stream/diagnostics modules; `db/schema.ts`, `migrations.ts`, diagnostic repository; `shared/chapter-contracts.ts` and typed channels; `services/jobs/lib/job-service.ts` orchestrates private chapter-aware primitives, not public methods with released busy locks; range render belongs in `media-service.ts` and derived subtitle compiler helpers; artifacts cache belongs with `runtime/artifacts.ts` and shared installer consumers. Do not introduce unrelated framework/refactors.

## Streaming lifecycle
Request starts with bounded metadata and owned response filename, obtains headers under profile deadline, then consumes the supported protocol stream with incremental UTF8/SSE parsing and bounded buffers. Handle OpenAI chat delta/finish/DONE (including usage-only chunks), Responses typed completion/failure, Anthropic event sequence/stop/error, Gemini finish/usage and DeepSeek keep-alive/reasoning activity. Write generated text in order with awaited backpressure; count heartbeat separately from actual content. Do not mix reasoning text into subtitle JSON.

Reset idle timing only for valid protocol activity; keep independent bounded overall duration. Default proposal: existing profile120s header/idle,30min text overall, configurable1–60min. All byte/JSON/provider finish/refusal/truncation guards remain. Idle/overall expiry or failure after output does not automatically re-POST. Bounded retry may remain for definite retryable HTTP responses before generation, with logged attempts; cancel aborts active reads and file writes before releasing lease.

Auto mode requests streaming; a200 non-stream JSON response can be handled within the SAME HTTP response and clearly logged as non-streaming. An unsupported-stream HTTP error offers explicit configuration/retry, not a second hidden billable request. Retained partial text is labelled partial; finalized complete text is still untrusted until strict operation validation. No salvage of missing JSON IDs/assessments. Non-stream compatibility cannot promise token-by-token partial recovery.

SQLite migration adds request/run diagnostic records with nullable job reference, profile/model/protocol snapshot, operation/chapter/run identity, target count/prompt bytes, start/header/first/last/end time, received bytes, actual optional usage, terminal/HTTP/error and owned file reference. Never persist API keys/authentication headers/full prompts in log columns. Pace progress writes and finalize once; storage failure is actionable and stops unsafe publication. Restart marks running entries interrupted, never resumes cloud calls. UI reads bounded diagnostics via allowlisted IPC; retention applies only terminal entries/files (30days/up to1000; active excluded). Explicit clear deletes only tracked owned files.

## Chapter contracts, source dependencies and planning
A normal plan is optional versioned Job metadata with ID/planRevision/source fingerprint/provider identity/created time/current-stale status and entries `{id,startMs,endMs,title,summary}`. Custom plans additionally snapshot criterion ID/version/name/text and kind. Bounds: at most500 entries, title120 UTF16 units, summary1000; strictly finite integral ms and0<=start<end<=duration, each <=1200000ms. Normal entries partition the whole media; custom entries are ordered non-overlapping with allowed gaps/empty success. Export selection is distinct from coverage.

Plan from chronological source text and original cue ordinal/time anchors, not translated output that would stale its own plan after translation. A fresh configured chapter service is explicit; the initiating translation/review can disclose reuse of its selected text service. Standalone chapter planning uses an explicit picker when unconfigured. The short automatic<=20min path needs one deterministic coverage chapter rather than a paid analysis; user-triggered AI splitting still analyses it.

Prefer topic/cue/overlap-cluster boundaries. Program-owned cap anchors handle long cue chains/silence; surface boundary-crossing cues in plan review. Source timeline is unchanged. Model recommendations beyond cap are split at validated anchors, retaining meaningful titles/summary and explicit subdivision. Validate complete coverage before publication; oversize source/request fails actionably, never drops unseen cues. Preserve user-edited plan and previous report until a successful explicit regenerate; source/mode/material analyzer changes stale derived applicability, style-only changes do not.

## Translation/checking orchestration
One main lease captures source/plan/provider/key/mode identity. Map each canonical target cue to exactly one coverage chapter using start-time ownership; context may cross boundaries. Translation uses chapter title/summary and deduplicated selected/context text under actual complete prompt/output guards. Dense chapters have visible bounded pieces. Default two workers (1–3 configurable), one coordinator serializes deterministic commits; no mutable-revision worker races. Whole translation validates a completed chapter before one content publication, preserving completed chapters on subsequent errors; fresh saved translations support explicit retry. Scoped/ASR-combined/repair operations retain all-target atomic drafting. Stop scheduling, abort/settle remaining requests and check freshness immediately before save.

Review gate is media.durationMs>1800000, not selection length. <=gate retains one complete selected-set request and existing explicit capacity limits. Above gate reuse normal chapters, partition requested IDs once, and call the existing review request builder with ALL original timeline cues so canonical groups/evidence/ordinals stay identical across splits. Never construct evidence from chapter-only or distant-selected chronology. Each chapter/work piece has strict complete target validation and at most the existing one corrective complete generation for correctable result defects.

Persist a backwards-compatible chapter review run with exact requested target coverage, chapter/piece states, completed/pending/failed IDs, provider/rubric/mode/source identities and timestamps. Each validated chapter merges only its targets' assessments/findings and matching context metadata under current freshness; preserve unaffected results/ignore intent. Extend explicit coverage/applicability contracts and UI so partial operation cannot be presented as complete/no-issues. Resume only pending compatible targets; stale source/context/provider/rubric forces explicit replan/recheck instead of trusting old coverage. Repair loop requires complete prerequisite analysis of its actual scope; partial initial/reassessment results remain saved but stop the loop with an honest failure/count state. Names uses full timeline through streaming and remains globally grounded, not chapter-isolated.

## Durable downloads
Cache is app-owned userData outside install candidates, keyed by pinned original URL/hash/size, with strictly parsed sidecar, actual `.part` length authority and optional verified complete payload. Acquire entry lock; request identity encoding; set Range at actual offset and legal strong If-Range. Validate206 single Content-Range start/total/end/body length before append.200 is a fresh full body, never appended.416 only completes after local exact-size/hash verification or resets boundedly. No strong validator: pinned final hash permits resumable range, and mismatch invalidates only owned entry. Reject compressed/malformed/overlong data.

Network/cancel/restart retains owned valid prefix. Verify fullsize/SHA256 before safe staging copy, then preserve existing extraction/native probes/atomic pointer activation. Do not consume verified cache before multiasset install succeeds. Cache clear is explicit/idle/entry-locked and confined; no TTL deletion of paused work. Recalculate remaining-cache+staging-copy+extraction free space. Status exposes bytes/asset identity/cache availability, not internal arbitrary paths. Unsupported Range restart is stated, not falsely called resumed. Existing online-video partial-directory cancellation cleanup remains unchanged.

## Criteria, UI and exact selected exports
Persist standards in a dedicated SQLite table/settings seed marker: initial core information, interesting moments, highlights. Bound name/body/count, clone with new ID, edit version, delete explicitly, one active standard per custom run. Removing selected standard clears selection; empty library stays empty across restart. Captured criteria snapshots remain provenance for old plans; a different selected standard does not relabel an existing plan or invoke AI automatically.

New chapter toolbar action follows style and precedes export. Bottom card exposes ordinary/custom mode, explicit planner/service/criterion action, bounded editable plan list, checkbox/all selection and seek. Criteria editor and diagnostics use existing one-close focus-restoring Modal. Long data scrolls locally; all required controls/footer fit native minimum. Existing right results card shows chapter/work counts and per-clip/request status.

Export input references job content revision, plan ID/revision, selected entry IDs and existing validated options. Main native directory selection precedes no-clobber filename allocation: sanitized title, reserved Windows names, duplicate case/trailingdot/length/existing files handled with bounded deterministic suffixes. Reuse trusted media rendering and codec/geometry/fonts; add real exact range support with clip-duration probe/decode. Derived subtitle timeline clips every half-open intersecting cue to range then rebases ms to clip zero; compiler/style/emphasis remain compatible. Audio delay/absence relative to source is retained through seeking/trimming/rebase tests rather than independent A/V PTS-STARTPTS assumptions.

Encode/publish each clip atomically, persist its status/output and keep successful clips on later error/cancel. Record pending/failed separately; restart marks batch interrupted. Retry verifies plan/source/options/file identity and handles missing/colliding files safely, never overwrites/deletes another file. Whole-video export remains unchanged. No concatenated montage, automatic publication or clean-video mode.

## Compatibility and verification
Bundled versioned SQLite migration and strict optional Job/profile defaults; old DB/profile/job fixtures load. Streaming affects text adapters only, and all new channels/preload outputs are allowlisted and typed. Capture new provider references in busy/save/remove staleness guards. Storage and file cleanup remain owned and cancellation safe; no debug test flags in packaged builds.

Fixtures test SSE partial chunks/UTF8/protocol terminal vs EOF/usage/heartbeat/first-idle-overall timers/cancel/backpressure and log restart; model requests never need live paid credentials. Chapters test20min caps,30min strict gate, sparse selection/cross-boundary evidence, partial publication/resume, duplicate/missing IDs, glossary and concurrency, atomic scoped failures. Downloads test actual byte offsets, range200/206/416/entity/hash and crash restart. Exports test actual FFmpeg A/V/subtitle boundary timing, duration/codec/geometry, names/collisions/cancel and historical files. Run full unit/integration+lint/typecheck, native end-to-end and three-size screenshot review, package startup/SQLite/resources checks. Record mock versus live-test limitations; no claimed guaranteed token/latency gains.
