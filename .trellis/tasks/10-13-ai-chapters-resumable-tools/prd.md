# AI chapters, translation and resumable tools

## Goal and value
Make long-video AI operations observable and recoverable, improve context with reusable content chapters, resume tool downloads, and export user-selected ordinary/custom chapters with useful names.

## Requirements and observable acceptance
### R1 — Streaming and SQLite diagnostics
Default text AI requests stream into uniquely owned local response files. Record request/run/job/operation/profile identity, model/protocol, prompt byte/cue counts, header/first/last/end times, response bytes, optional actual usage, attempt/status/error and file reference in SQLite. Logs omit keys/auth headers/full prompts. Preserve received text after failure/cancel/restart; partial JSON never counts as valid subtitles/review/names/plans. Show actual waiting/receiving/validating phases and elapsed time. Distinguish header/idle/overall deadline and network/HTTP failures; do not silently regenerate a long deadline-expired or partially emitted response. Preserve protocol refusal/truncation and cancellation rules. Verify delayed/chunked local fixtures, partial-file persistence, request counts and SQLite restart records.

Reviewable defaults:120s existing profile timeout governs text header/idle waiting; an independently configurable text-generation ceiling defaults30min, range1–60min. Stream compatibility supports automatic same-response JSON handling and explicit non-stream mode without a hidden duplicate POST. Terminal diagnostic records/files retain30days/up to1000 requests, with explicit clear for completed records; active work is never pruned. A diagnostics entry is available from the existing results area.

### R2 — Shared chapter planning
Normal chapters partition the whole source timeline, are chronological/non-overlapping and <=20min each, with title/summary/range. Custom plans are separate ordered non-overlapping selected intervals and may leave gaps or be empty. Validate all model data before storing it, preserve prior plans on failure, and bind plans to source/media/language fingerprints and plan revision. Prefer cue/topic boundaries; if a single cue/overlap chain/silence prevents the hard cap, expose program-owned time boundaries without changing canonical subtitles. Users can edit titles/summaries/ranges, seek and select chapters. Reuse current normal plans for translation/checking/export instead of paying for repeated planning.

### R3 — Default chapter translation
Chapter translation is the default for translated projects; source-only never translates. Automatic short videos<=20min use one coverage chapter without an extra planning request; explicit AI chapter planning remains available. Longer videos use content-based plans. The planner uses the explicitly configured chapter service, or the initiating operation's already-selected text service, disclosed in UI. Dense chapters use bounded visible work units and deduplicated context rather than repeated whole-chapter text. Independent chapters use bounded concurrency (default2, configurable1–3). Preserve IDs/times/unselected text. Completed full-translation chapters survive cancellation/failure and retry only stale/missing work; scoped/combined/repair operations still draft the complete target and save atomically. Measure actual request/prompt/output counts instead of promising latency/token/accuracy gains.

### R4 — Long-video chapter checking with retained results
At duration>30min, divide only the requested review targets by normal chapters; exactly30min or shorter keeps one complete selected-set logical request. Each cue is owned by one request while evidence groups/ordinals are computed from the ORIGINAL full timeline, including cross-chapter neighbours. Every request requires complete coverage of its own targets. Save validated completed chapters incrementally, as explicitly approved by user `保留`; show completed/pending/failed coverage, leave missing/stale results honest, and offer resume of remaining compatible chapters. Never mark an incomplete run complete or fill missing assessments with none. Preserve ignore/freshness/rubric/provider/revision semantics. A repair loop stops on incomplete prerequisite analysis while retaining earlier valid results/content; it never repairs using an assumed all-clear. Names remains global across chapters for variant identities.

### R5 — Resumable managed tools/models
Cover Whisper CPU/GPU archives, all three models, yt-dlp and Deno. Stable pinned-identity partial/verified cache survives network failure, cancellation and restart independently of ephemeral install staging. Resume with validated Range/Content-Range/entity encoding/validator handling; never append a full200 response. Final size/SHA256 and native probes are mandatory before activation. Missing legal HTTP validator may use pinned-identity range plus final full hash; changed entity/hash failure resets only that cache entry. Servers ignoring Range restart that asset transparently with a stated reason. Preserve old usable installations and completed earlier assets. Display retained byte progress/resume and explicit cache clear; do not auto-download on opening/restart. Keep paused downloads until explicitly cleared. Verify actual transferred offsets/bytes across graceful and abrupt interruption.

### R6 — Custom criteria and chapter exports
UI label is `自定义切分章节`; criteria are general user goals, not only highlights. Provide editable initial standards for core information, interesting moments and highlights, with add/edit/copy/delete/select. One active standard per custom generation; persist versioned content and immutable snapshots in plans. Deleting a selected standard clears that selection rather than choosing silently; deleting all standards does not recreate them on restart. Existing saved plan snapshots remain inspectable.

Export checked ordinary/custom chapters using existing MP4/MKV or SRT/ASS/VTT modes and subtitle/style/codec/resolution/quality options. Main chooses a directory; each title becomes a safe bounded Windows filename, with deterministic suffixes for duplicate/reserved/existing names and no overwrite. Clip at exact validated ranges, rebase derived subtitles (including boundary overlaps) and preserve source A/V timing offsets. Keep already verified completed clips when later clips fail/cancel; expose per-clip status and retry only missing compatible outputs. Canonical source subtitles/media remain unchanged. No montage concatenation or extra clean-video mode.

### R7 — Compatibility, UI and verification
Use strict optional/versioned Job metadata and a bundled SQLite migration, typed allowlisted IPC and one main-owned cancellable operation lease. Legacy jobs/profiles remain readable; no startup resumes paid AI/export/download. New chapter action follows style and precedes export, with icon/label; its natural-height bottom card, one-close dialogs and local long-content scrolling must remain usable at1050x700/1440x960/1920x1080. Results/progress remain in the existing combined right card. Delegate independent review, run lint/typecheck/full unit/integration, native Electron flows and actual FFmpeg/SQLite/download-stream fixtures; mock AI proves integrity, not model accuracy. Finish with local commit and a verification installer after approved implementation.

## Scope boundaries and risks
No GitHub release/push or paid provider calls. Online-video download resume and developer/CI asset downloading are separate scope; ordinary whole-video export remains available.20min is not a model token capacity guarantee. Unsupported streaming/range needs honest compatibility behaviour. Partial responses cannot reliably resume an interrupted remote generation without provider support; retained chapter results and diagnostic text survive, but incomplete individual generations require explicit retry. Logs cannot retroactively recover old missing traces. Download cache/staging copies need updated free-space accounting.
