# Research: AI chapters, highlight criteria and range export

- Query: Design content-based chapters (each at most 20 minutes), reusable chapter translation, configurable highlight selection and safe chapter media/subtitle export within Slice Man.
- Scope: mixed (repository contracts and official FFmpeg documentation)
- Date: 2026-10-13
- Status: planning only; proposals below are not implemented behavior.

## Latest user decisions (2026-10-13)

These decisions supersede the earlier highlight-only wording and optional chapter-translation assumption below:

- Chapter translation is the **default** translation path. Normal semantic chapters must cover the full video and each remain at most20minutes; provider token budgets can require smaller requests inside a chapter without changing its visible semantic range.
- For video duration **greater than30minutes**, AI subtitle review operates by chapter. The dispatched decision does not specify whether exactly30minutes changes behavior, so use the stated strict `durationMs > 1_800_000` boundary unless parent confirms otherwise. Review selected cues only; chapter/global context remains read-only evidence.
- The optional mode is named **自定义切分章节**, not a hardcoded highlight mode. Saved standards are general user policies (e.g.topic cuts, core explanations, funny highlights), not necessarily interesting-moment criteria.
- Exactly **one saved standard is active per custom generation run**. No combination of multiple standards/prompts. Snapshot its ID/version/name/instructions immutably with the result; subsequent library edits or deletion do not rewrite existing plan provenance.
- Normal/full-coverage and custom plans are separate saved results; a custom plan cannot replace normal translation/review coverage.
- Both modes present editable title, summary and time range plus per-entry export checkbox. Time edits are main-validated; selecting or editing entries does not automatically rerun AI or export.
- Selected chapter exports use the same MP4/MKV/SRT/ASS/VTT formats and options as existing whole-job export, with safely derived unique title-based output names. No newly implied montage or clean-video format.

### Minimal coherent integration after these decisions

1. Reuse the existing selected review text profile for **semantic chapter generation and custom generation**, with clear label in chapter UI; use existing translation profile solely for translation. This is a proposed default, not a new user decision. No new provider protocol, key store or materially different profile type is needed. If review profile is absent/unusable, show the existing explicit text-service picker before generation rather than silently use style/cloud recognition. Parent may choose a dedicated optional chapterProfileId if separation is needed; that adds dependency invalidation and UI scope but is not blocking.
2. A source-grounded normal plan is shared by default translation and long-video review. Its source fingerprint survives translated text publication; its boundary/title edits increment separate plan version. Current source edits or ASR/name changes mark it stale. Translation/review use canonical cues rather than exported/rebased clip cues. Default translation may visibly generate an absent/stale normal plan under one operation lease; opening UI never generates it. Reuse a current approved/current plan without another planner request.
3. Store optional `normalChapterPlan` and `customChapterPlan` separately, each with own ID/version/state/provenance. Custom includes one immutable standard snapshot; normal needs no user standard. User-edited ranges are constrained mechanically: normal partition remains complete/non-overlapping and each<=20minutes; custom may omit unwanted regions and returns distinct non-overlapping clips unless explicitly extended to another semantics later.
4. Keep a compact `章节` toolbar action before export, containing standard selector+manage and a `自定义切分章节` checkbox plus explicit generate. Show current plan list with editable title/summary/range, original-video seek and checkboxes. Preview/export names derive from persisted plan entries, not unsaved input. Save reviewed edits once through strict IPC, then export selected entries via existing options. The list can scroll locally while execute/footer remains visible at1050×700.
5. Rename proposed library/service/contracts from highlight-specific wording to **chapter cut standards**. Suggested application-local file `chapter-cut-standards.json`; UI `切分标准`, `新增`, `复制`, `删除`, `选择`. Seed default standard explaining interesting/core/complete passages, but arbitrary valid user standards may focus on topic boundaries or another requested subset. Criterion only governs segmentation preference, never transport/filesystem/schema constraints.
6. Exports still need a batch primitive with clear complete/failed/not-started outcomes. Recommend per-clip atomic publication with completed clips retained on cancel; normal and custom plan IDs/versions plus Job revision pin each run. Existing single-output export is unchanged.

### Only blocking product choice remaining in this research scope

The parent is already clarifying **incremental visible AI review results versus one final atomic review publication**. Repository evidence: existing selected review protects the previous complete report on failure; incremental translated batches already survive later failure. With chapter review, either policy can be implemented safely, but user-visible truth differs. If incremental is chosen, persist only completed chapter assessments, retain unrelated/prior still-compatible assessments, identify pending/failed chapters explicitly, and never display unreviewed chapters as none/all-clear. Keep one lease, per-chapter grounding and staleness checks. If atomic is chosen, collect all drafts and publish only a complete validated selected set, retaining previous report throughout. The outcome affects apparent speed and repair-loop eligibility, so do not invent it silently.

No other product choice above requires blocking planning: provider reuse, deterministic filename suffixes, selected formats, default criterion contents, optional sidecars/metadata and per-clip retention can be stated reviewable defaults within the requested scope. Do not ask again about already-decided name, default translation,30-minute review threshold or standard multiplicity. All-or-nothing filesystem batch export is technically possible but is an additional product preference; defaulting to retained completed clips is coherent with existing completed-translation behavior.

### Recommended reusable chapter plan

Use a new shared strict `chapter-contracts.ts`, a main-owned planner/validator module and optional versioned Job metadata. Suggested plan: `{version,id,kind:'chapters'|'custom',createdAt,providerId,providerFingerprint,sourceFingerprint,standardSnapshot?,state:'current'|'stale',entries:[{id,startMs,endMs,title,summary,evidenceCueIds}]}`. Keep `planRevision` separate from content Job revision; export input references both so plan edits, replacement and source changes cannot redirect an in-flight export. Bound count/title/summary/evidence sizes and reject duplicate/unknown entry/cue IDs, NaN, fractional ms, negative times, reversed/out-of-media bounds and duration>1_200_000ms before publication. Never interpret missing/invalid output as an empty successful plan.

Content identity should include source cue IDs/times/text, language and source identity/duration. If planner uses translated text, also include translation mode/content and stale flags; simplest reliable default is chapter analysis from source text so later chapter translation does not immediately stale its own plan. Style edits need not invalidate source semantic chapters, but export still uses current Job revision/style. Criterion or model change marks compatible AI plan stale; retain old reviewed plan as historical data. Store criteria text/version snapshot in each report so deleting a library item cannot destroy saved plan provenance.

Normal chapters and custom cuts have different coverage validations. A normal plan partitions `[0,media.durationMs)` continuously in order without gaps/overlap; first/last boundaries are program-owned, including intro/outro silence. Custom cuts may have gaps and an empty valid result when no material meets the selected standard, but should be ordered and non-overlapping to prevent duplicate exports. Do not reuse sparse custom plans as translation/review coverage.

Ask AI for chapter boundary anchors (observed cue IDs/ordinals and permitted boundary IDs) rather than unrestricted invented seconds. Main precomputes canonical millisecond boundary candidates and resolves returned anchors; it verifies full cue/media coverage and the hard20-minute ceiling. Prefer boundaries between complete overlapping cue clusters, using existing silence near topic changes. **Cue-boundary-only partitioning cannot guarantee20 minutes:** one long cue, overlap chains or prolonged silence can exceed20 minutes. Include deterministic program-owned fallback time anchors at the cap; show any crossing cue and proposed split for review. Exact cue text/timing remains canonical and unchanged; exported boundary cues are clipped only in the derived clip timeline. Do not silently expand chapter ranges past20 minutes to accommodate crossing cues.

AI titles/summary are suggestions, not ground truth. UI should list range, duration, title, summary and selected checkbox with preview seek; allow title/summary edits and validated boundary edits, explicit regenerate, select all and export selected. Proposed numerical bounds (e.g.title120units,summary1000,500entries) require choosing in design rather than treating these as existing schema facts. Preserve prior good plan on provider failure/cancel/stale snapshot.

### AI capacity and translation reuse

One semantic chapter can be20minutes but have far more text than a provider input/output budget. Duration is not a token bound. A chapter planner can use bounded chronological source windows, produce grounded compact summaries/boundary suggestions, then reconcile adjacent windows under a global outline. Distinguish this implementation from a full literal transcript in one request; preserve global topic continuity explicitly. No model-controlled timestamp mutation. Share the task's provider request budget, structured JSON response/truncation/timeout handling and cancellation rather than let new chapter analysis reproduce current whole-timeline timeout behavior.

Full chapter translation should target canonical cue IDs exactly once, preserving their original timing. For crossing boundary cues, assign ownership deterministically (e.g.chapter containing cue start) and include them as read-only context elsewhere; never duplicate translation commits or replace original timestamps with clipped export times. Sparse selected translation is selection∩chapter owned cues; other chapter text is context only. Use source chapter title/summary and a compact global names/glossary summary for continuity without repeating the entire transcript in every request. Budget-based smaller requests remain necessary when one chapter response cannot fit; disclose these as chapter sub-batches, not an unbounded silent fallback. Retain completed chapter translation checkpoints and stale/revision guards, consistent with existing completed-batch retention. Never enable/call translation in source-only projects. Reusing a current normal plan avoids another paid chapter analysis; do not auto-run chapter/highlight analysis on toolbar open.

### Persisted user-managed cut standards

Recommend separate application-local `ChapterCutStandardsService` with a versioned strict library and atomic main-owned JSON persistence, following ExportSettingsService's write-ownership pattern. Record `{id,name,instructions,version,createdAt,updatedAt}`, selected ID, and at least one seeded default. Users may add/edit/copy/delete/select; copy creates a fresh ID, deleting selected item picks a predictable remaining entry; reset/default restoration is explicit. Test zero/custom-only list behavior before choosing whether the final item may be deleted. Do not silently re-seed deleted defaults at every restart. Exactly one selected standard and its immutable snapshot apply to each custom generation run.

Default content can favor complete interesting stories, informative core explanations, notable reactions or funny moments, excluding repetition, routine intros/outros, ads and empty talk, while preserving enough setup/payoff. No promise of visual/action highlights from subtitles alone; the current system has text analysis, not multimodal video understanding. Titles/summary should state content rather than fabricated visual events.

Prompt structure: application instructions/schema/time bounds first; **selected criterion is authorized user policy for content preference**, clearly delimited and limited to ranking/inclusion; subtitle text/language/title strings are untrusted evidence data, never instructions. Criterion cannot override schema, file destinations, provider secrets, source preservation or timing limits. Return evidence cue IDs and reasoning grounded in observed text; validators enforce mechanical constraints independently of any prompt wording. Plain string concatenation of criteria with transcript must not erase this separation.

### Correct clip media and subtitle export

Add a dedicated range rendering primitive or a final optional validated range option; preserve all legacy whole-video and PNG preview callers. Treat ranges as original video playback offsets in milliseconds. Build a derived cue view for `[a,b)`: include `cue.startMs < b && cue.endMs > a`, set `startMs=max(cue.startMs,a)-a`, `endMs=min(cue.endMs,b)-a`, retain ID/source/translation/style and discard only zero-duration intersection. Compile against `durationMs=b-a`, original display geometry and mode. ASS emphasis still keys by original IDs. SRT/VTT clocks restart at0 for each standalone clip; ASS centisecond rounding must retain current <=9ms serialization exception without extending media.

Current `render` filter/ffmpeg duration verification must change for actual clipped video; filtering only cues cannot shorten video. Select an accurate decoded range and ensure video timestamps reaching libass are clip-relative; test subtitle at nonzero original times, not just first frame. Preserve original source audio offset: independently resetting video and first available audio sample to0 can collapse a genuine audio delay. Model the expected audio portion/delay relative to `[a,b)`, including wholly silent clips and ranges crossing late audio start; original `media.hasAudio` cannot blindly be the expected audio flag for every clip. Do not add recognition's audioOffset to chapter times: they already use the video timeline.

Keep controlled filter/ASS paths and argument-array construction. Never insert title, summary or criterion into FFmpeg expressions/paths. Reuse font/caption geometry/codec/AAC validation. Probe **range duration** rather than source duration, decode meaningful first/middle/last frames, verify subtitle pixels/text and audio sync on actual output. Frame/sample quantization requires explicit bounded tolerance; a textual20-minute maximum must not be a minute-long silent media overrun. Check actual long-source/non-keyframe middle clips and VFR, rotation/SAR/nonzero timestamps, not only synthetic first-second clips.

### Names, destinations and batch cancellation

Main owns native destination **directory** selection once for the batch; renderer references plan/entry IDs and export options. Resolve actual output paths from saved validated titles in main. Preflight all planned names and source-path protection; preview final names before encode. Sanitization must include Windows controls and `<>:"/\\|?*`, trailing dots/spaces, empty/dot names, reserved device stems (CON/PRN/AUX/NUL/COM1..9/LPT1..9 including extensions), Unicode-safe length/path budget and traversal. AI names never become absolute or relative directory paths. Distinguish title from output basename so visible titles remain intact.

Recommend ordinal+title (`01 - Title.mp4`) or deterministic suffixes for duplicate sanitized titles. Existing on-disk names require new suffix or explicit selection of another directory; final `publish()` remains authoritative against races. Do not use `rename()` with possible replacement or `access()` as an overwrite guarantee. A fresh exclusively created export-run subdirectory reduces collisions but changes the user-visible output layout and should be decided in planning.

Recommended batch semantics: one lease; encode one clip at a time; each verified clip publishes no-clobber and immediately persists its output/run entry; cancellation/failure removes only owned current temporaries, retains completed clips and historical outputs, and stops remaining work. Display `completed / failed / pending` with exact paths, not a false whole-batch success. Retry only missing/failed entries from a still-current plan and matching export options; skip verified completed files. This mirrors existing completed-translation retention but is a product choice, not existing batch behavior. If all-or-nothing is desired instead, stage all clips then publish a fresh batch directory; do not pretend a database transaction can atomically roll back independently visible filesystem files. Publication→SQLite-save failure needs explicit reconciliation/run metadata; never delete a possibly user-modified prior output during generic cleanup. Startup running batches become interrupted and offer user-triggered retry.

### UI integration

Recommended toolbar chapter action before export, SVG icon+label; a compact bottom card for provider, normal/highlight toggle and selected criterion, then a bounded plan list/editor. Criterion management can use one Modal with focus restoration and one close. Export selection/options reuse ExportForm controls without forcing a two-column layout, keep natural bottom alignment and1050×700 required controls reachable. Use the existing right results card for analysis/export progress and per-entry results; do not introduce a second persistent status stack or hide export under settings. No auto provider/encode calls on opening, choosing an existing criterion or selecting chapter rows. Preview seek must use original `startMs`, while exported clip time is rebased.

## Caveats / Not Found

- No existing chapter/custom-cut schema/service/UI/export range or editable policy library found. This is new cross-layer behavior, not a parameter toggle in existing export.
- Latest decisions above resolve editable ranges, default chapter translation, long-video review threshold, one standard per custom run, separate normal/custom plans and existing export formats. Dedicated chapter provider, optional sidecars/JSON manifest, default standard contents, per-clip retention and filename layout remain reviewable implementation defaults, not additional blocking questions. Montage and clean export remain additional scope.
-20-minute semantic context cannot promise lower total tokens or faster response in every video/provider. Analysis adds cost; reusable plans and smaller repeated instructions may save overhead, while full-context oversized generation can increase latency. Measure actual input/output/request counts instead of asserting savings from duration alone.
- Long-cue/overlap/silence makes strict cue-only boundaries incompatible with guaranteed maximum duration; surface deterministic fallback explicitly rather than claiming both constraints always hold.
- Current source identity uses size/mtime, not a cryptographic content hash; this existing limitation should not be described as full source-integrity proof.
- No source code, specs, task state or Git state changed by this researcher; only this research file was written.
