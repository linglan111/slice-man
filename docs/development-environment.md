# Windows development environment

Validated on Windows 11 x64 build 26200. Windows 10 remains a separate clean-device acceptance check.

## Prerequisites and installation

Use Node.js 24.17.0 x64 (npm 11.13.0) or a compatible later Node 24 release. The package engine and lockfile pin the supported toolchain/dependencies. Python, a compiler, the CUDA development toolkit, and administrator access are not prerequisites for the application or this pinned prebuilt dependency combination.

From the repository root:

```powershell
npm ci
npm run setup:resources
npm run setup:whisper-fixtures
npm run test:native
npm run test:media
npm run dev
```

`setup:resources` downloads and verifies a pinned FFmpeg 8.1.2 essentials archive and Noto Sans CJK SC Regular/Bold fonts, includes their notices, and acquires the installation smoke-test audio. Required resources are ignored binary files and are regenerated by this command on a fresh checkout. The script does not modify system drivers or install a system FFmpeg. `setup:media` is an optional developer diagnostic that copies an existing PATH FFmpeg with its DLLs; release packaging uses `setup:resources` instead.

The Noto font family is **Noto Sans CJK SC**; the managed regular/bold files are in `resources/fonts`. FFmpeg and ffprobe are static x64 executables in `resources/media`; runtime data, speech models and credentials belong in application-managed user data, rather than this resource directory.

## Commands

```powershell
npm run lint
npm run typecheck
npm test
npm run test:coverage
npm run test:e2e
npm run build
npm run package
npm run make
npm run test:package
npm run test:installer
```

`build` produces `out/main/index.js` and `out/preload/index.js` as CommonJS and the renderer in `out/renderer`. Main externalizes native dependencies; preload bundles its Zod validation and other dependencies (`externalizeDeps: false`) so it works inside Electron's sandbox. electron-builder includes production dependencies and extracts better-sqlite3 from ASAR, plus media, fonts, notices and smoke audio as resources. Versioned SQL migrations are compiled from `src/main/db/migrations.ts` into the main bundle. `package` produces `dist/win-unpacked`; `make` produces the per-user x64 NSIS installer. These local builds are unsigned, so SmartScreen/signature acceptance must be verified before publication.

`test:package` launches the actual unpacked binary with isolated user data and verifies production startup/native IPC/resources, including rejection of development-only environment overrides. `test:installer` first checks current-user/system app registry entries and shortcut collisions; if any existing Slice Man installation could be affected, it reports a skip and leaves it untouched. Otherwise it silently installs the current NSIS artifact into the fixed workspace `.native-smoke/installed-app` directory, launches the installed executable with separate user data, checks native IPC/resources, silently uninstalls, and verifies removal of its executable/registry/shortcuts. Its report is `.native-smoke/installer-report.json`. All install/uninstall subprocesses are hidden; cleanup is restricted to the resolved, non-junction test target. This developer-device installation proof does not replace clean-machine or Windows 10 testing.

If a user is running the portable application from `dist/win-unpacked`, build the next release in a separate output directory. Never replace, rename or delete the running portable folder. Use the verified Electron ZIP described below and the builder's per-invocation output override:

```powershell
npm run package -- "--config.electronDist=$releaseElectronZip" --config.directories.output=dist/release-0.1.4
npm run make -- "--config.electronDist=$releaseElectronZip" --config.directories.output=dist/release-0.1.4
npm run test:package -- --app-dir dist/release-0.1.4/win-unpacked
```

The optional `--app-dir` selects only the smoke-test executable/resource directory; it accepts ordinary directories inside the workspace's `dist`, rejects escaping paths/junctions and retains `dist/win-unpacked` as its default. Smoke-test user data remains separate under `.native-smoke`. The standalone installer can be copied, with overwrite disabled, to `dist/Slice Man Setup 0.1.4.exe` for the existing read-only `test:installer -- --inspect` preflight without changing previous portable folders. Do not install or upgrade over a running user's application during this validation.

## Native speech verification

Prepare test fixtures on a fresh checkout before desktop E2E/native speech tests:

```powershell
# CPU fixtures: pinned CPU runtime, Base model and public JFK sample (~152 MB).
npm run setup:whisper-fixtures
npm run test:whisper -- --cpu
npm run test:e2e -- --grep-invert "actual CUDA desktop"

# Optional NVIDIA fixtures: additional ~460 MB CUDA runtime archive.
npm run setup:whisper-fixtures -- --gpu
npm run test:whisper
npm run test:e2e
```

`setup:whisper-fixtures` streams pinned artifacts, verifies exact size/SHA-256, safely extracts CPU and optionally CUDA packages into `.runtime-cache/whisper`, and preserves an old extracted fixture until its replacement succeeds. It revalidates cached files on repeated runs. These are developer test fixtures; production still uses the application's managed install. On a GPU host with prepared fixtures, the current deterministic suite includes ten desktop flows; otherwise the CUDA E2E explicitly skips for unavailable fixtures/device. CPU-only commands above deliberately exclude that CUDA test. Live-provider tests remain opt-in and skip without their separate configured credentials.

`test:whisper` exercises the actual RuntimeService install using the pinned CPU/CUDA archives and Base model replayed through a local HTTP cache, then runs CPU/CUDA inference on the official 11-second JFK sample. `--cpu` exercises the same install/inference path with CPU only, without requiring CUDA files or a NVIDIA GPU. The helper reports missing artifacts explicitly rather than substituting mock inference. Cache replay avoids downloading the same large artifacts again. It does not count as a live AI-provider test.

To explicitly run the paid DeepSeek text tests, prepare the CPU fixtures, supply `DEEPSEEK_E2E_API_KEY` in the test process environment through a secure local credential handoff, set `APP_LIVE_DEEPSEEK=1`, and run `npm run test:e2e -- tests/e2e/deepseek-live.spec.ts`. The tests use `deepseek-flash` at the official endpoint, real local recognition and actual translation/style requests; they do not call cloud speech. Without both environment prerequisites they skip. Do not embed a key in shell command text, tracked files or reports. The live suite disables trace/video/failure screenshots, uses session-only profiles and clears isolated credentials/data after each test. Clear the parent environment after the run as well.

The first real model/runtime downloads and checksums, actual CUDA log, CPU fallback, wall/inference timings and GPU/driver matrix are recorded in the task's `research/environment-report.md`. `small` and `large-v3-turbo` integrity metadata is pinned, but this environment validation does not claim benchmarking those larger models.
